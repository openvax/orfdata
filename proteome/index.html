    Build a reference proteome¶

    A Proteome holds protein sequences for one species and genome. It is built in explicit layers: annotated proteins first, then optional extra ORFs and viral proteins. Each method returns a new proteome. proteome.layers records every addition with its role (host, viral or filter), source, selection and counts, and each entry lists every transcript that encodes it.

    from pyensembl import EnsemblRelease
from orfdata import Proteome

genome = EnsemblRelease(115, species="human")  # Installed with pyensembl install.
annotated = Proteome.from_genome(genome)
proteome = annotated.with_extra_orfs(evidence="ms")

    The examples on this page continue that Python session.

    Annotated proteins¶

    Proteome.from_genome(genome) takes every transcript with an annotated protein sequence. For Ensembl this matches the annotation's protein FASTA: Ensembl 115 has 245,535 human proteins with 160,811 distinct sequences. They include nonsense-mediated-decay and immunoglobulin/T-cell receptor segment translations, and 11,540 proteins on patch, haplotype and unplaced contigs. Each entry records its accession, gene, transcript, contig and transcript biotype, so you can restrict them explicitly:

    primary = {str(n) for n in range(1, 23)} | {"X", "Y", "MT"}
chromosomes = annotated.filter(lambda e: e.contig in primary, description="primary chromosomes")
print(len(chromosomes))

    233995

    filter records its description and the number of removed entries as a layer. Mouse, dog, yeast and other PyEnsembl species work the same way; mouse Ensembl 115 has 66,668 annotated proteins. orfdata does not download or index annotation data. An uninstalled genome raises an error naming the pyensembl install command.

    Choose the evidence¶

    with_extra_orfs(evidence=...) selects catalogue ORFs by evidence and adds each one that a transcript of this genome encodes: the transcript contains the ORF's exact spliced coding path and translates to its protein. Counts below are for the bundled human catalogue (dataset 2026-10-11.1) and Ensembl 115:

    Selection Human ORFs Encoded in Ensembl 115
    evidence=None or "all": every catalogue ORF 7,264 7,239
    evidence="ribosome" or "riboseq": translated in ribosome profiling 7,264 7,239
    evidence="ms" (default): any supporting MS peptide 2,186 2,181
    evidence="immunopeptidomics": peptides eluted from MHC (in human, HLA) molecules 1,881 1,879
    evidence="ms_unclassified": MS with an unreported assay type 537 535
    evidence="proteomics": peptides from digested cellular proteins 73 72
    "ms" with require_unique=True 1,623 1,621
    "ms" with require_reviewed=True 44 44

    All bundled ORFs come from ribosome-profiling catalogues, so "ribosome" selects all of them. An MS-supported ORF can have peptides from several assay types. require_unique keeps peptides that map to one protein within the MS source's search, which is not uniqueness across every possible protein; in this catalogue only the author HLA ligand mappings report it. require_reviewed keeps peptides with convincing community spectrum reviews. Because those two properties come from different sources, no bundled peptide has both. require_resolved excludes support that consists only of aggregate counts. See ORFs and evidence for the full definitions.

    A list (or tuple or set) of names selects ORFs with any of them: evidence=["proteomics", "immunopeptidomics"] keeps ORFs with either kind of MS peptide, unlike "ms", which also counts unclassified MS. For ORFs that need two kinds of evidence at once, combine rules with &, below.

    Separate Ribo-seq and MS stringency¶

    For more control, pass a rule. RiboSeq(min_studies=n) needs ribosome profiling in at least n independent studies the source names, and MS(min_peptides=n, unique=..., reviewed=..., mhc=...) needs at least n distinct supporting peptide sequences. MS(mhc=True) counts only peptides eluted from MHC molecules (the immunopeptidome) and MS(mhc=False) only peptides from digested cellular proteins (the whole proteome). MS() counts both, and the MS peptides whose source doesn't say which. methods= names the kinds directly, for combinations such as ("proteomics", "ms_unclassified"). & requires both rules and | accepts either:

    from orfdata import MS, RiboSeq

annotated.with_extra_orfs(RiboSeq(min_studies=2))                        # replicated Ribo-seq
annotated.with_extra_orfs(RiboSeq(min_studies=2) & MS())                 # Ribo-seq and MS
annotated.with_extra_orfs(RiboSeq(min_studies=2) | MS())                 # either
annotated.with_extra_orfs(RiboSeq() & MS(mhc=True))                     # Ribo-seq and an MHC ligand
annotated.with_extra_orfs(MS(methods=("proteomics", "ms_unclassified")))  # not immunopeptidomics-only
    Rule Human ORFs Encoded in Ensembl 115
    RiboSeq(min_studies=2) 3,085 3,072
    RiboSeq(min_studies=3) 1,675 1,671
    MS(min_peptides=2) 682 681
    MS(methods=("proteomics", "ms_unclassified")) 610 607
    RiboSeq(min_studies=2) & MS() 1,296 1,293
    RiboSeq(min_studies=2) & MS(min_peptides=2) 457 456
    RiboSeq(min_studies=2) \| MS() 3,975 3,960

    GENCODE's c…riboseqorf… IDs are the 3,085 ORFs seen in two or more studies. Each method name above is the simplest rule: "ms" is MS(), "immunopeptidomics" is MS(mhc=True), "proteomics" is MS(mhc=False) and "ribosome" (or "riboseq") is RiboSeq(). The names before 0.28.0 ("shotgun", and "mhc" or "hla") still work, with a deprecation warning, and catalogues that use them still load. A peptide counts once however many assay types report it, and so do peptides that differ only by I and L (equal in mass). Nested peptides, such as MHC ligand length variants, count as one: the count is the largest set of supporting peptides none of which lies inside another, so a long peptide never hides two shorter, separate ones, and a stricter rule always selects a subset of a looser one. Of the 916 ORFs with two or more distinct peptide sequences, 234 have fewer than two that aren't nested. Each rule in & is checked on its own: MS(mhc=False) & MS(unique=True) needs a proteomics peptide and a unique peptide, not one unique proteomics peptide. A source's aggregate count stands for one observation: it satisfies RiboSeq() and MS() but never min_studies or min_peptides above 1, unique, reviewed or resolved=True. The layer stores the rule, so a snapshot records exactly how its ORFs were chosen; EvidenceRule.from_dict reads it back. Equal rules are stored the same way, whatever their order or repeats, so they give one proteome identity.

    A translated ORF or a detected peptide does not by itself establish a stable, functional protein. Missing evidence does not establish that an ORF is never translated.

    Every transcript, and excluded ORFs¶

    Each extra ORF is one entry, whatever the number of transcripts encoding it. entry.occurrences lists them, the transcript the source names first. Each Occurrence has the transcript and gene, start and end slicing the transcript sequence, the genomic coding_blocks and on_source_transcript. Annotated entries have one occurrence, on their own transcript.

    from collections import Counter

ms_orfs = [e for e in proteome if e.kind == "extra_orf"]
print(Counter(min(len(e.occurrences), 5) for e in ms_orfs))
print(Counter(e.reason for e in proteome.excluded))

    Counter({5: 1253, 1: 345, 2: 254, 3: 184, 4: 145})
Counter({'ORF splice path mismatch': 5})

    More than half of the MS-supported ORFs, 1,253 of 2,181, are encoded by five or more Ensembl 115 transcripts. The bundled models were validated against Ensembl 101, and later releases retire or change some of their transcripts. When an ORF's source transcript is gone or changed but another transcript still encodes it, the ORF is added and entry.source_binding gives the reason: 41 of the MS-supported ORFs, counted as not_on_source_transcript in the layer. The 5 in proteome.excluded are encoded by no Ensembl 115 transcript. identical_to_annotated in the layer counts added ORFs whose protein now matches an annotated protein; both entries are kept because they have different identities and evidence. proteome.by_sequence() groups entries with identical sequences, for example before an exact peptide search.

    Without catalog=, load_catalog picks the catalogue for the genome's species and assembly: a bundled one, or else one installed through CatalogRegistry, several merged. Human GRCh38 has the bundled one, and mouse GRCm39 three once installed; for other species the error names the catalogues that exist. Pass catalog= to use another, such as load_catalog(path). A catalogue for a different species or assembly is rejected.

    Merging catalogues¶

    Pass several catalogues for one species and assembly to use their ORFs together:

    from orfdata import load_catalog, merge_catalogs

catalogs = [load_catalog(), load_catalog("study-orfs.json.gz")]  # The bundled one and a local file.
proteome = annotated.with_extra_orfs("ms", catalog=catalogs)  # Or merge_catalogs(catalogs).

    Records from different catalogues are one ORF when they have the same spliced coding path, protein, genetic code and start codon; declaring a start the code already uses, such as ATG, changes nothing. Records within one catalogue stay as it gave them. A record joins an ORF found on its own transcript before any other.

    • IDs. The merged ORF keeps the first catalogue's ID. Every source's record stays in record.members, and the others' IDs are in equivalent_ids as source:id. catalog.get and ExtraORFs.for_orf accept any of them.
    • ID collisions. When two sources use one ID for different ORFs, both become source:id, and the bare ID raises rather than picking one.
    • Evidence. Each source's evidence is kept, and evidence rules see the union: a peptide counts once per sequence. A Ribo-seq study two catalogues label differently counts once when their ribosome_study_pmids metadata give it the same PMID, as the bundled catalogue's does; without PMIDs it counts twice toward RiboSeq(min_studies=...).
    • Lookups. Queries by transcript, gene or biotype, for_transcript and ExtraORFs.for_gene(..., source=True) match every source's labels, and an ORF is on its source transcript when it is on any source's.
    • Annotation pins. Sources pinned to different annotation releases of the assembly leave the merged ORF unpinned; each member keeps its own pin.
    • Rejected merges. Catalogues must share a strain, where an unknown strain counts as its own value, and must not repeat a source, so two releases of one catalogue can't both be merged. A merged catalogue can be merged again.
    • Conflicts. catalog.metadata["conflicts"] lists ORFs that share a coding path but differ in protein, genetic code or declared start codon.

    The layer's source joins the catalogues' releases, such as orfdata-catalog:2026-10-11.1+orfdata-catalog:study-v1. On the command line, repeat --catalog FILE.

    Viral proteomes¶

    A ViralProteome holds one virus's proteins, its NCBI taxon, and the NCBI species taxa recorded as its hosts, with the source of that host range. It can only be added to a proteome for one of those hosts:

    from orfdata import ViralProteome

# Template: substitute your FASTA, the virus taxon and your host-range source.
hpv16 = ViralProteome.from_fasta(
    "hpv16-proteins.fasta", name="HPV16", taxon_id=333760,
    host_taxon_ids={9606}, host_source="Host range source and date",
)
with_virus = proteome.with_viral(hpv16)

    Adding it to a mouse or dog proteome raises an error. orfdata does not infer hosts from a virus's name or from related viruses. Viral entries keep the virus's taxon, and their layer has the role viral; proteome.host() returns the host's own proteins without them, for example as a self reference.

    Save and reload¶

    identity = proteome.save("human-e115.proteome.json.gz")
same = Proteome.load("human-e115.proteome.json.gz")  # Offline: no genome or catalogue needed.
assert same.identity == identity

    A snapshot holds every entry with its occurrences and evidence, the layers with their selections and catalogue identities, and the excluded ORFs. identity is the SHA-256 of that content, so it changes when any sequence, occurrence, selection, catalogue or exclusion changes, but not with file compression or formatting. Loading rejects a snapshot whose content does not match its identity, host proteins from another species, viral proteins without a matching host layer and layers declaring another reference. The human Ensembl 115 proteome with MS-supported ORFs is a 57 MB snapshot that saves in about 8 s and loads in about 11 s. Saving is deterministic: the same proteome gives the same bytes.

    Cache a built proteome¶

    Proteome.build makes the usual proteome in one call: from_genome, then with_extra_orfs(evidence, catalog=...) and with_viral for each of viral=. With cache=True it keeps the result in the OpenVax DataCache root (ORFDATA_CACHE, OPENVAX_DATA_CACHE, or cache_root=). cache_root= is also where the species' registered catalogue is looked for, with or without cache=True:

    proteome = Proteome.build(genome, RiboSeq(min_studies=2) & MS(), cache=True)

    The cache key is the reference, evidence rule, catalogue and viral identities, snapshot schema and orfdata version. A later identical build, from any program, loads that verified snapshot, so tools share one identity. For human Ensembl 115 with MS-supported ORFs, the first build takes about 30 s, including saving, and later ones about 7 s. A cached snapshot is checked by its DataCache checksum, so it skips the re-serialization load does. Local annotation files of a custom genome are fingerprinted by size and SHA-256, so genomes that share names never share an entry. Entries of a cached or loaded proteome don't carry orf; use extra_orfs(genome) for ORF objects. Each cached build sits next to a recipe.json recording its key and identity. Nothing is downloaded, and extra_orfs=False builds the annotated proteome alone.

    Lower-level ORF lookup¶

    extra_orfs(genome, evidence=None) returns every catalogue ORF on every transcript carrying it, as TranscriptORF objects, with source_failures and excluded. Its default selects no evidence level: use it for annotation, such as variant effects on uORFs, where the proteome's MS default would be the wrong scope. Look ORFs up with for_transcript and for_gene; see identifiers for how versions and references are checked. for_transcript(transcript, include_annotated=True) adds the annotated CDSs on that transcript, and overlapping(...) finds ORFs at a genomic interval.

    FASTA headers¶

    write_fasta writes 60-column sequences. The first word of each header is the accession: an Ensembl protein ID with its version, a source ORF ID or a viral protein ID. Fields that apply follow as key=value:

    >ENSP00000269305.4 kind=annotated taxon=9606 source=ensembl:115 gene=ENSG00000141510 gene_name=TP53 transcript=ENST00000269305.9 contig=17 transcript_biotype=protein_coding
>c7riboseqorf56 kind=extra_orf taxon=9606 source=orfdata-catalog:2026-10-11.1 gene=ENSG00000169902 gene_name=TPST1 transcript=ENST00000304842.6 contig=7 transcript_biotype=protein_coding orf_type=uORF evidence=ribosome,immunopeptidomics transcripts=18
>c10riboseqorf115 kind=extra_orf taxon=9606 source=orfdata-catalog:2026-10-11.1 gene=ENSG00000099204 gene_name=ABLIM1 transcript=ENST00000369253.6 contig=10 transcript_biotype=protein_coding orf_type=intORF evidence=ribosome,immunopeptidomics source_transcript=ENST00000277895 transcripts=10

    For extra ORFs, the accession is the source ORF ID, transcript is its host transcript in this genome, and gene, gene_name and transcript_biotype describe that transcript in this genome. orf_type is the source's ORF category, kept verbatim; see ORF categories. evidence lists the supporting evidence types. transcripts counts the encoding transcripts when there are several, and source_transcript names the source's transcript when the header's transcript is a different one, as for ABLIM1 above, whose source transcript is gone. See also identifiers. The snapshot keeps every occurrence; the FASTA header shows the first.

    Command line¶

    orfdata proteome --species human --release 115 --output human-e115.fasta
orfdata proteome --species human --release 115 --extra-orf-evidence all
orfdata proteome --species mouse --release 115 --extra-orf-evidence none

    --extra-orf-evidence accepts the evidence names above, all for every catalogue ORF, or none for annotated proteins only. --require-unique, --require-reviewed, --require-resolved and --catalog FILE match the Python options. Rules have their own options:

    orfdata proteome --species human --release 115 --min-ribo-seq-studies 2 --min-ms-peptides 1
orfdata proteome --species human --release 115 --min-ribo-seq-studies 3 --min-ms-peptides 2 --either
orfdata proteome --species human --release 115 --min-ms-peptides 1 --ms-methods proteomics,ms_unclassified

    Given both a Ribo-seq and an MS requirement, an ORF needs both unless --either is set. --require-unique and --require-reviewed refine the MS requirement, and --require-resolved both. The FASTA goes to --output or standard output; --snapshot FILE also saves a snapshot, and --cache reuses or keeps the build in the cache; --cache-root DIR chooses the cache, for catalogues as well as builds. A JSON summary of the layers, identity and excluded ORFs goes to standard error.

    Not yet included¶

    Mouse noncanonical ORFs come from Chang et al.'s and Yang et al.'s Ribo-seq and OpenProt's MS catalogues once you install them; see Mouse. Dog noncanonical ORFs, and translated endogenous retrovirus (ERV) ORFs without annotated transcripts, need new source data; see the data roadmap. Products from circular RNAs, stop-codon readthrough or non-AUG starts can be described with TranscriptORF.at and SourceRNA (see the examples), but no bundled catalogue supplies them yet, so proteomes do not include them.
